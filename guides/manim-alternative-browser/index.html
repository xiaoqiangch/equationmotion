Manim without Python

The engine is portable now. Whether that helps you depends on which of its three jobs you actually need.

Job 1 — run the real engine in a tab

Pyodide builds of Manim Community compile the actual Python package to WebAssembly and shim Cairo to a 2D canvas. You write real Scene classes and get real output, with a LaTeX-ish typesetter standing in for TeX. The catch is weight: the first load pulls tens of megabytes of runtime, and anything that depends on a native TeX distribution degrades to a subset.

A lighter variant compiles Manim's own code to a much smaller runtime and keeps the familiar API. It is impressive, and it is still a programming interface — it removes the install, not the coding.

Job 2 — a visual timeline over the engine

Several editors put a timeline on top: drag a text or LaTeX object, add a transform, export. This is the friendliest path for teachers, and the most work to make look good, because the easing and the pacing are now yours to set.

Job 3 — just write the line on screen

Most educational equations are not geometry. They are a line of type that should appear, then the next line. For that, a full engine is a lot of machinery, and the write-on reveal is the whole feature.

What I would actually do

Keep Manim installed for the one scene per video that needs a real transformation. Use a write-on renderer for the twenty equations around it. The mix sounds inelegant and is what most working channels end up doing anyway — the tool follows the shot, not the other way round.
